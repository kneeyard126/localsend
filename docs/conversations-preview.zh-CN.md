# 局域网会话体验版

这个实验分支在 LocalSend 原有协议上增加按设备组织的会话。打开「会话」选择附近设备，输入文字或添加文件即可发送。桌面支持 Enter 发送、Shift+Enter 换行、中文输入法组合输入和拖放附件；手机宽度使用单栏界面。

## 已实现

- 发送和接收的文字、文件记录按证书身份合并；设备改 IP 后可使用发现得到的新地址。
- 每个接收设备使用发送队列，连续发送不会争抢 LocalSend 的单会话接收入口；不同设备可以分别传输。
- 显示排队、传输进度、送达、拒绝、取消和失败；支持取消及重新发送。
- 文本草稿和附件按设备暂存；会话支持查找、复制文字、打开链接、打开收到的文件和清空记录。
- 关闭原有「保存历史记录」后，新会话只保存在内存中。历史记录最多保留 1,000 项，清空会话不会删除实际文件。
- 仅当前选中的加密会话可直接接收证书身份匹配的短文字；其他设备仍显示接收界面，文件保留原有确认流程。
- 短文字使用 LocalSend 的 inline preview。超过 16 KiB UTF-8 的文字完整地作为文本文件传输，避免把超长文字放进预览界面。

## 兼容性与限制

- 使用现有 LocalSend v2 协议；旧版客户端仍通过原来的文字接收界面处理消息。双方都使用此分支时才有双方的会话界面。
- 「已发现」表示发现缓存中有该设备，不保证它此刻在线；历史地址不可达时会显示发送失败。
- 文件接收会进入原有的确认和进度页面。尚未实现聊天内接收文件、群聊、后台消息推送、断点续传、未读计数或跨设备同步历史。
- 已完成 macOS Apple Silicon 原生构建和自动测试。Windows、Linux、Android、iOS 代码共用 Flutter 界面，但尚未完成各平台实机验收。
- 本地 macOS 包为临时 ad-hoc 签名，未经 Apple 公证；未验证 Share Extension。这不是 LocalSend 官方发布版本。
- 内存附件的重试缓存限制为 100 项 / 32 MiB；重启后只能从仍存在且可访问的本地文件或已保存的短文字重新发送。

## 验证

- `fvm flutter analyze --no-pub`：无问题。
- `fvm flutter test --no-pub`：149 项通过，覆盖消息历史、序列化写入、关闭历史后的隐私、TLS 身份隔离、发送队列、取消、错误恢复、桌面快捷键、聚焦输入框草稿同步和手机大字体布局。
- macOS 原生 loopback 验证：证书匹配的会话文字返回 HTTP 204 并直接显示；中文消息通过粘贴入口发送并收到确认。37,888 字节附件发送后与源文件逐字节相同；102,000 字节旧客户端长预览按文件确认接收，内容完整。重启后会话文字和文件记录恢复。此测试使用本机协议测试端，不代表 Windows / 手机实机验收。
- 本分支包含早先的长文字与剪贴板修复。上游 PR [#3737](https://github.com/localsend/localsend/pull/3737) 只提交范围明确的长文字 bug 修复；会话功能在独立实验分支维护。

## 构建

遵循仓库 `.fvmrc` 和 `CONTRIBUTING.md`，先 `fvm flutter pub get`，从 `app/` 执行对应平台的 Flutter 构建命令。macOS 本地构建需要完整 Xcode、CocoaPods 和 Rust 工具链。
